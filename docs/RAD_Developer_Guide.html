2. Data Layout: Zero-Copy Combinatorics

To avoid deep copies of heavy particle objects (like TLorentzVector), RAD separates Topology (Indices) from Data (Momentum Arrays)[cite: 461].

  • Input: Flat RVecs (rec_px, rec_py...) containing all tracks in the event[cite: 481].
  • Map: ReactionMap. A matrix of indices pointing to the flat arrays. The physics engine performs integer lookups directly[cite: 482].
  • Output: Variables are calculated column-wise in a single pass using SIMD vectorization[cite: 482].

3. Parallel I/O: SnapshotCombi & Masking

Lock-Free TTree Writing

Writing TTrees from multiple threads typically causes segmentation faults[cite: 485]. RAD handles this safely via SnapshotCombi, designed specifically for ROOT::EnableImplicitMT()[cite: 462, 485].

  • Thread-Local Buffers: Pre-allocates buffers and TTree instances based on the thread pool size[cite: 486].
  • Context Safety: Guards gDirectory to prevent file operation crashes during the event loop[cite: 487].
  • Lazy Flattening: Flattens nested combinatorial outputs (Event → Combination) into a clean N-Tuple[cite: 488]. Event-level scalars (like Truth Beam Energy) are automatically broadcasted across all combinations[cite: 501, 502].

Lazy Masking vs. Filtering

Standard Filter() drops events entirely, ruining sideband analyses[cite: 489]. RAD employs a Masking strategy:

  • PhysicsSelection generates a boolean mask column[cite: 490].
  • Trees and histograms only process entries where the mask is true, preserving underlying array alignment[cite: 491, 492].

4. Deep Dive: Extending the Managers

How to map complex data sources and inject auxiliary detector information.

Injector Podio/EDM4hep Data Mapping

For EIC and ePIC data, truth matching is handled via Podio association arrays (e.g., ReconstructedParticle2MCParticle)[cite: 493, 494].

The ePICReaction Implementation:

// ePICReaction automatically traverses association arrays // using the rad::PodioAssociations utility class. rad_df.SetupMatching(); // This allows developers to map Object IDs seamlessly to the correct // MC Truth particle index without manual looping. rad_df.DefineTrueMatchedCombi("rec_is_signal", rad::Rec());

Modifier Auxiliary Data Injection

Propagating low-level detector data (like Calorimeter Energy or Track Chi2) directly into the combinatorial engine[cite: 498].

How to Extend:

// 1. Define the raw column from the data source (e.g., Calorimeter Energy) rad_df.DefineAssociation("clusters", {"EcalBarrelClusters"}, "energy"); rad_df.DefineProjection("rec_cal_energy", "rec_clusters_energy", "rad::util::First"); // 2. Pass it to the Pre-Modifier // This aligns "rec_ele_cal_energy" with the electron candidate indices, // ensuring the correct hit is associated with the correct track. kine.PreModifier().SetMomentumFrom("ele", "rec_cal_energy");
